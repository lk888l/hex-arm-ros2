## 日常启动与停止

机械臂从断电折叠参考 `[0,-1.570,3.140,0,0,0]` 开始。
入口在使能前检查静止反馈和位置；J1/J5 容许 0.03 rad 摆放差异，J2/J3/J4 容许 0.01 rad，
同时必须满足本机窗口。小偏差保留原零偏，J6 在允许范围内按需平滑回零。

在宿主机仓库目录的图形终端执行：

```bash
HEX_ARM_CAN_IFACE=can2 ./scripts/docker-dev.sh up
HEX_ARM_CAN_IFACE=can2 ./scripts/docker-dev.sh real-launch moveit \
  /workspaces/hex_arm_ros2/config/hardware/firefly_y6.meow.can2.local.yaml \
  enable_execution:=true
```

默认依次执行 **J2→−1.350（8 s）、J4→−0.300（10 s）、J3→3.000（6 s）**，
其余关节最终为 0；未轮到动作的 J2/J3/J4 保持实测位置。该折叠退出路径由操作者确认实物无碰撞，
使用固定关节轨迹；后续 MoveIt 运动保留严格碰撞检查。

等待 `startup_ready reached and verified; controller continues holding` 后，在 RViz 选择
`arm`、当前状态作为起点，再使用 `Plan` / `Plan & Execute`。
`startup_ready:=false` 为使能后原位保持；省略 `enable_execution:=true` 为观察/规划。

停止时在拥有 real-launch 的终端按 Ctrl-C，等待 `VERIFIED clean controller exit`。
切换上位机、修改硬件配置或重新编译前，先结束当前控制端。

CAN 名称由参数和 profile 选择，并核对 USB 序列号与物理通道。换口时在控制停止后运行
`scripts/bind-can-profile.py`，保留本机身份、方向、零偏及调试参数；详见
[Meow 部署说明](meow_mit_deployment_cn.md)。

## 后续优化顺序

1. **闭环重复性**：保持当前增益，重复不同姿态的正反向小步和保持试验；纳入 J2 回程情况，
   根据实际误差决定是否调整单轴 Kp/Kd、重力系数或摩擦补偿，每次只改变明确的一项参数。
2. **模型和限位**：核对实际行程、零偏、碰撞网格及桌面/底座环境，统一 URDF、MoveIt 与硬件范围。
3. **扩大工作空间**：先单轴，再多轴联动；逐段开放位置窗口，通过后再提高速度和加速度。
4. **连续运行与恢复**：验证重复上电、顺序启动、连续轨迹、较长时间保持、温度、通信中断停机和恢复。
5. **固化部署**：固定软件版本、最终 profile、设备绑定和启动/停止入口，完成一次完整操作流程验收。
   后续加夹爪或载荷时更新模型与负载参数，再验证相关工况。
