# can2 支撑轴与展开准备记录（2026-09-29）

本记录接续[单轴扩大行程验收](2026-09-29-can2-expanded.md)。本阶段使用旧 CiA402
revision 9、更换后的同一条无附加载荷机械臂、同一组软件零偏，保持 `calibrated: false`。
用户授权直接调试、使用重力补偿和逐档调参。尚未完成六轴 ROS/MoveIt 真机执行验收。

原始材料位于 `.tmp-cia402-supported/`；可版本管理的
[完整结果](2026-09-29-can2-supported-result.json)保存每次命令、配置快照、二进制与日志哈希、
独立读数和失败原因。配置/二进制随调试阶段变化，不能用最终源码哈希代替每次试验的二进制哈希。

## 实现与参数

新增显式命名支撑轴模式：只使能选中轴及 `--support-axes` 指定的轴，支撑轴先使能，
选中轴最后使能。全部失能时配置并回读原有驱动限幅；以位置 PD 和零重力前馈使能，
按关节侧 `1 Nm/s` 渐入 `G(q)`，稳定后才执行运动。每轮退出确认六轴失能并解除心跳，
批量脚本随后独立读取六轴状态。

| 轴 | Kp / Kd | 重力比例 | 用途 |
|---|---|---|---|
| J2 | 200 / 8 | 1.0 | 保持或顺序准备 |
| J3 | 200 / 8 | 0.8 | 保持或 −0.015 rad 往返 |
| J4 | 80 / 4，后改为 80 / 6 | 0.5 | 保持或顺序准备 |

原有速度、加速度和力矩限幅不变：速度/加速度各 0.1 SI；J2/J3/J4 软件力矩
分别 6/7.5/1.5 Nm；电机总力矩分别 200/250/200‰，PD 100‰。
J1/J5/J6 保持失能。原始零偏配置未覆盖。

准备顺序为 J2 正向、J4 负向，每步 20 秒半余弦轨迹。目标容差使用原有 0.005 rad，
连续稳定 0.5 秒才通过；尚未运动的使能轴仍受 0.003 rad 保持限制，失能轴漂移限 0.005 rad。
先前新模式把准备到达容差也写成 0.003 rad，导致 J2 在 0.003162 rad 残差下失败；
随后统一到已有的 0.005 rad 轨迹目标标准。命令参考始终保持原值，没有重置到实测位置。
准备动作只在主试验通过后逆序返回，任何失败均停机，因此失败不代表已按顺序返回折叠位置。

## 十次动力试验

| 试验目录 | 结果 | 观察 |
|---|---|---|
| `j3-j4-hold` | 通过 | J3/J4 重力保持 |
| `j3-j4-small` | 失败 | J3 实测峰值 −0.005143 rad，回程误差 0.004705 rad；J4 支撑消除了先前的被动漂移 |
| `j234-hold` | 通过 | J2/J3/J4 同时保持 |
| `j234-prepare-hold` | 失败 | J2 准备到达误差 0.003162 rad，未达到最初的 0.003 rad 门槛 |
| `j234-prepare-hold-goal` | 通过 | J2 +0.03、J4 −0.03、J3 保持及逆序返回全部通过 |
| `j234-prepared-j3-small` | 失败 | J4 准备末段速度 0.117773 rad/s 触发限速；J3 往返尚未开始 |
| `j234-kd6-prepare-hold` | 通过 | J4 Kd 从 4 调至 6，相同准备/保持/返回流程通过 |
| `j234-kd6-j3-small` | 失败 | 0.03 rad 准备后，J3 峰值 −0.005291 rad，回程误差 0.003648 rad，未达到位移目标 |
| `j234-kd6-prep006-j3-small` | 失败 | 0.06 rad 准备后，J3 峰值 −0.005059 rad，回程误差 0.003762 rad |
| `j234-kd6-prep012-j3-small` | 失败 | 0.12 rad 准备后，J3 峰值 −0.005029 rad，回程误差 0.003796 rad |

共 4 次通过、6 次失败。扩大准备的两轮均完成 J2/J4 到达检查，但整个往返试验未通过，
不能视为完整展开/返回流程验收。J3 力矩峰值约 5.57～5.65 Nm，现有数据不能单独区分
摩擦、实物方向或接触限制，也不能据此宣称驱动总力矩已经饱和。

每轮控制器日志均确认六轴失能。0.06/0.12 rad 准备的两轮，立即独立读取时 J2 仍因
失能卸载移动，采样跨度分别 0.004198/0.029109 rad，批量程序因此停止，未继续其他动作。
后续独立读取 `after-prep006-settled.json`、`after-prep012-settled.json` 均确认六轴静止、
状态字 `0x0231`、故障码 0、心跳消费者 0。较大展开姿态下的卸载下落仍是部署前需处理的问题。

## 碰撞与方向核对

各准备路径分别使用无 CAN、不可执行的严格 SRDF 离线实例采样 121 个状态。
相对于初始折叠的 `link_1/link_5`、`link_2/link_4`，没有新增碰撞对；
这不等于整条路径严格无碰撞，也不授权绕过 MoveIt 碰撞检查。

用户最初未看清小幅 J3 运动。停止动力试验后，用户报告通电失能时手动展开有阻力。
随后只读核对得到六轴 `0x2040=1`、控制字 `0x0006`、模式 0：旧固件失能时保留短接制动，
因此该手动观察不能证明机械卡死。用户进一步确认**断电后 J3 可以轻轻展开**。
未远程修改制动设置；需要独立的展开位置编码器读数核对物理方向，不能直接翻转 profile 符号。

新增离线 `check-joint-direction.py` 比较同一机械臂两份失能静止快照与操作者已知的
URDF 运动方向；拒绝错臂、跨单圈、位移过小和其他轴明显运动，不修改配置。
具体步骤见[零点与方向说明](../zero_calibration_cn.md)。

批量脚本即使独立静止检查失败，也保留失败读数到总报告。这些改进发生在上述动力试验之后。
